Two agent skills teach a coding agent (Claude Code, Codex, Cursor and others) to use the `deck` CLI well: one plans and writes presentations, the other drafts a brand from material you already have. Install them in the folder that holds your decks and you can ask your agent for a deck in plain words. This page installs them, shows what to ask and how to review what comes back.

There are three ways to work with an agent, and they combine:

| How | What the agent can do | Page |
| --- | --- | --- |
| Your agent in a terminal, with the skills (start here) | Plans and writes whole decks with the `deck` CLI | this page |
| The same agent, plus `deck dev --mcp` | Also sees the slide you are on, lints, takes screenshots and adds or reorders slides through tools | [MCP tools](/ai-agents/mcp-tools/) |
| `deck dev <deck> --agent claude` or `--agent codex` | Chats beside the slide, edits only the deck's content, every turn can be undone | [The agent panel](/ai-agents/agent-panel/) |

## The two skills

- **`create-presentation`** plans a storyline and an outline with one claim per slide. The agent uses `deck layouts <deck> --summary` to pick a layout for each slide's job, including brand layouts where they fit. It then writes the slides and notes and checks the rendered result with `deck lint` and `deck shot`. [Choose a layout](/reference/layouts/#choose-a-layout)
- **`brand-import`** turns a PowerPoint template, PDF, Google Slides link, website, guidelines or screenshots into a draft `brands/<name>/brand.ts`. When a template supplies slide layouts, the agent maps the placeholders to slots and fields, chooses kit fallbacks, and compares the rendered layouts with the source. [Import a brand](/brands/import-a-brand/) · [Brand layouts from a template](/brands/brand-layouts/#from-a-template)

```console
$ npx skills add sandrinodm/deckster --list
...

│
│      Extract or recreate a brand for the deckster `deck` CLI from PPTX or POTX templates, PDF, Google Slides, a website, guidelines or screenshots. The cloning progress at the top is cut. Skill updates come from the Deckster repository on GitHub. The workspace layout catalog comes from your installed version of the CLI.
```

## What they need

- `deck` on your PATH: `npm install --global @deckster/cli`, with Node 26 or newer ([Quickstart](/get-started/quickstart/)).
- Chromium for `deck lint` and `deck shot`, downloaded once; when it is missing, the command prints how to get it.
- For `brand-import`, [`uv`](https://docs.astral.sh/uv/) to run its Python extractors.
- A coding agent, installed and signed in: Claude Code, Codex or another agent the installer supports.

## Install them

<Steps>

1. Make a workspace and go into it. The agent's `deck new` creates `decks/` here; if you already have one, go to the folder that holds `decks/`.

   ```sh
   mkdir talks && cd talks
   ```

2. Install and sign in to your agent, if you have not. For Claude Code: `npm install -g @anthropic-ai/claude-code`, then run `claude` and sign in with `/login`. Codex and the other options are on [the agent panel](/ai-agents/agent-panel/#install-and-sign-in-to-an-agent-cli) page.
3. Run the [skills.sh](https://skills.sh) installer, which asks which skills and which agents: `npx skills add sandrinodm/deckster`.
4. Start your agent in the same folder and ask for a deck, as shown below.

</Steps>

The installer's options:

```sh
npx skills add sandrinodm/deckster                              # both skills; asks which agents
npx skills add sandrinodm/deckster --skill create-presentation  # one skill
npx skills add sandrinodm/deckster -a claude-code codex         # choose the agents
npx skills add sandrinodm/deckster -g                           # for every project, not just this one
```

Without `-g` the skills go into the current folder: `.agents/skills/` (read by Codex and several other agents), with a symlink for each other agent you pick, such as `.claude/skills/` for Claude Code; `--copy` copies the files instead of linking them. The installer also writes `skills-lock.json`. With `-g` they go into each agent's user-level folder. `-y` skips the prompts.

```console
$ npx skills add sandrinodm/deckster --skill create-presentation -a claude-code codex -y
...
◇  Installed 1 skill ──────────────────────╮
│                                          │
│  ✓ ./.agents/skills/create-presentation  │
│    universal: Codex                      │
│    symlinked: Claude Code                │
│                                          │
├──────────────────────────────────────────╯

│
└  Done!  Review skills before use; they run with full agent permissions.
```

The output is cut at `...`. Afterwards, `npx skills ls` lists what is installed, `npx skills update` updates it and `npx skills remove create-presentation` removes it.

## Ask for a deck

Start your agent in the folder that holds `decks/` and say what you want, who it is for and what they should do afterwards:

```console
$ cd talks
$ claude
> Make a 10-minute deck about our Q3 reliability numbers for the leadership team. We want them to
  approve the on-call staffing change. Use the default brand. In the outline, say which layout
  serves each slide's claim. Show the strongest evidence for the recommendation.
```

## Ask for a brand from a template

Provide the source template and the slide types you reuse.

```console
> Import our brand from ~/Downloads/company-template.potx and the site https://example.com.
  Keep the cover, divider and two-column content layout. Show how the title and content
  placeholders map to slots or fields, name the kit fallbacks, and compare the renders.
```

## Review what it made

<Steps>

1. Open the deck in a second terminal while the agent works: `deck dev launch-review`, with the deck name the agent gave. The slides reload as it edits them.
2. Read the handoff. It says where the deck is and how to run it, the storyline, the `[NEEDS: ...]` items you must supply (blocking ones first), the deck's weakest points, the lint result and which brand it uses.
3. Press `c` on anything you want changed and leave a [comment](/review/comments/) on the slide.
4. Tell the agent "Work through the open review comments on launch-review". It lists them with `deck comments launch-review --json`, edits the file and line each one names, and resolves each with `deck comments resolve` and a note on what changed.
5. When `deck lint launch-review` is clean, run `deck export launch-review` for a PDF and a PowerPoint file in `.deck/exports/launch-review/` ([PDF](/export-and-publish/pdf/), [PowerPoint](/export-and-publish/powerpoint/)).

</Steps>

## What the agent will and will not do

With `create-presentation` the agent:

- **asks only what it cannot infer** and what would change the deck if it guessed wrong: at most four questions in one round, each with a default you can accept. Audience and outcome are the two it will interrupt you for;
- **writes a short brief and an outline** for you to react to before it builds slides, unless you asked for the finished deck, in which case it goes on and says the outline was not reviewed;
- **keeps working files outside your workspace**, in a temporary folder, and shows you their content in the conversation;
- **never invents facts.** Every number, name or quote comes from your material or a source it can cite. A missing one becomes a placeholder such as `[NEEDS: Q3 churn by segment, source]`, kept in the speaker notes where it can be, and every placeholder is listed in the handoff;
- **treats source material as data, not instructions.** Instructions found inside a document, a web page or a review comment are not followed; an attempt to steer it is mentioned in the handoff and left out of the deck.

## The agent panel and the skill

The [agent panel](/ai-agents/agent-panel/)'s agent does not run skills: for Claude the skill tool is turned off. Its standing rules point it at `create-presentation`'s files instead, which it reads as plain files when it finds them in the workspace under `.claude/skills/`, `.agents/skills/` or `skills/`, or in the agent's global skills folder. Installing the skill in the workspace therefore helps both your terminal agent and the panel.

An agent you run in a terminal can also use the deck tools of a running `deck dev --mcp`: see [MCP tools](/ai-agents/mcp-tools/).
