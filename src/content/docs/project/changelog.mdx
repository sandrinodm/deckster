## v0.11.0

[Release notes](https://github.com/sandrinodm/deckster/releases/tag/v0.11.0).

### Code layouts

A brand or a deck can bring layouts written as React code, for a structure the kit's layouts and a brand's data layouts cannot hold. Each sits in `layouts/<name>/` with a `contract.ts`, which declares the layout's frontmatter, slots, budgets, optional checks and PowerPoint mapping, and a `layout.tsx`, which draws it. Slides name a code layout like any other, `deckster layouts` lists it with the kit's, and `deckster lint`, the build and PowerPoint export work from its contract. A problem with a layout fails the slides that use it with the problem's own id, such as `layout-contract-invalid` or `layout-name-mismatch`. [Code layouts](/brands/code-layouts/) · [Check a code layout](/brands/code-layout-checks/) · [PR #45](https://github.com/sandrinodm/deckster/pull/45)

### Replace a kit layout, eject and diff

A code layout with `replaces: true` takes the place of the kit layout of the same name, and slides keep their frontmatter as long as the replacement accepts it (`layout-replace-breaks` says when it does not). `deckster layouts eject <layout>` copies a kit layout into your brand or deck as a code layout to start from, and `deckster layouts diff` shows how your copy has moved from the kit's. [Replace a kit layout](/brands/replace-a-kit-layout/) · [PR #45](https://github.com/sandrinodm/deckster/pull/45)

### `deckster layouts new` and `deckster layouts check`

`deckster layouts new` writes a contract and component to start from. `deckster layouts check` loads each code layout, renders it at its budget limits in Chromium and reports each problem with a fix. [CLI reference](/reference/cli/#deckster-layouts) · [PR #45](https://github.com/sandrinodm/deckster/pull/45)

### Code layouts and trust

A code layout is code that runs on your machine. `deckster brand add` never copies a fetched brand's code layouts and lists the ones it left out in `.deckster-source.json`. An agent turn cannot write a layout file, and contracts are held while a turn runs. Before a contract runs in the build, deckster checks its imports and runs it first in a separate Node process with a deadline, which catches hangs and accidental file, network, process or environment use early; neither check is a sandbox. [Code layouts and trust](/brands/code-layouts-and-trust/) · [PR #45](https://github.com/sandrinodm/deckster/pull/45)

## v0.10.1

[Release notes](https://github.com/sandrinodm/deckster/releases/tag/v0.10.1).

### Cropped SVG drawings no longer fail `canvas-overflow`

The slide `deckster new slide <deck> <id> --layout image-reveal` writes failed `deckster lint` with two `canvas-overflow` errors. Its placeholder drawing uses `preserveAspectRatio="xMidYMid slice"`, which crops it like a photo with `object-fit: cover`, and the rule measured each cropped shape in full. `canvas-overflow` now measures a shape inside an inline `<svg>` by the part the `<svg>` shows, unless the `<svg>` has `overflow: visible`; the `<svg>` itself is still checked. [Lint rules](/reference/lint-rules/) · [PR #42](https://github.com/sandrinodm/deckster/pull/42)

## v0.10.0

[Release notes](https://github.com/sandrinodm/deckster/releases/tag/v0.10.0).

### Placed elements: `<Shape>`, `<Text>` and `<Place>`

Put a callout, badge, stamp, label, icon or short list anywhere on a slide, outside the layout's slots. `<Shape>` draws a box in one of seven geometries (`rect`, `square`, `ellipse`, `circle`, `pill`, `diamond`, `triangle`) with brand colours and fitted text, `<Text>` sets type without a box, and `<Place>` positions any kit component or Markdown block. Position them by a named place inside a zone, a cell of the brand's 12×6 grid or, as a last resort, a pixel box. They don't count against a layout's slot limits, corner chrome makes way for them, and seven `placed-*` lint rules catch one that leaves the canvas, covers text or says too much. A brand can set its grid's rows with `spacing.grid.rows` (default 6). PowerPoint exports a shape as one native shape with its text and a `<Text>` as a native text box. [Placed elements](/write-slides/placed-elements/) · [Lint rules](/reference/lint-rules/) · [PR #40](https://github.com/sandrinodm/deckster/pull/40)

### The `image-reveal` layout

A two-step layout: the slide opens as a full title cover, and on the next step the title, eyebrow and subtitle slide into a bar docked at the bottom (or top) while the image fills the rest of the slide. `dock`, `align`, `barSurface`, `fit` and `focal` set how it looks, and the lookbook has four examples. The kit now has 64 layouts. [image-reveal](/reference/layouts/image-reveal/) · [PR #38](https://github.com/sandrinodm/deckster/pull/38)

### `deckster present` no longer shows a running dev server's deck

`deckster present` could take the same port as a `deckster dev` server that was still running, because one listened on `127.0.0.1` and the other on `localhost` (`::1` on macOS), and the window could then show the dev server's deck. The dev and preview servers now listen on `127.0.0.1` unless you pass `--host`, so `deckster dev` prints `http://127.0.0.1:5173/`. `deckster present` serves the deck on a free port the operating system picks unless you pass `--port`, and warns when a dev server for the workspace is still running. [Present on one screen](/present/deck-present-and-displays/#present-on-one-screen) · [Troubleshooting](/present/troubleshooting/#the-window-shows-an-older-version-of-the-deck) · [PR #39](https://github.com/sandrinodm/deckster/pull/39)

## v0.9.0

[Release notes](https://github.com/sandrinodm/deckster/releases/tag/v0.9.0).

### The command is now `deckster`

**Breaking.** The CLI installs a `deckster` command instead of `deck`, and there is no `deck` alias. After upgrading, use `deckster` in scripts, CI workflows and agent instructions: `deck dev` becomes `deckster dev`, and in a clone of the repository `pnpm deck` becomes `pnpm deckster`. The deck files, `deck.config.ts` and the `DECK` and `DECK_ROOT` variables are unchanged. [CLI reference](/reference/cli/) · [PR #35](https://github.com/sandrinodm/deckster/pull/35)

### Download Electron with `deckster electron`

npm, pnpm and yarn often skip Electron's download when they install `@deckster/cli`. `deckster electron install` downloads the version the CLI was built with, `deckster electron update` replaces a binary left by an older CLI, and `deckster electron status` reports what is on disk. A failed download names the cause, such as missing write permission, the network or proxy, or a checksum mismatch. `deckster present` now prints `deckster electron install` when the binary is missing. [Download Electron's binary once](/present/deck-present-and-displays/#download-electrons-binary-once) · [PR #37](https://github.com/sandrinodm/deckster/pull/37)

### Animation timing in published decks

A production build wrote the brand's durations in seconds (`.64s`), and diagrams, code transitions and count-ups read them as milliseconds, so they played almost instantly. They now run at the authored speed. [PR #33](https://github.com/sandrinodm/deckster/pull/33)

### Security updates

Vite+ moves to 1.7.0, which fixes two advisories in earlier versions ([GHSA-5qr3-w62x-jmwx](https://github.com/advisories/GHSA-5qr3-w62x-jmwx), [GHSA-p79r-mf8q-r78h](https://github.com/advisories/GHSA-p79r-mf8q-r78h)). Effect, Playwright (1.65.1), Electron (45.4.1) and the icon sets are updated too. [PR #34](https://github.com/sandrinodm/deckster/pull/34)

## v0.8.0

[Release notes](https://github.com/sandrinodm/deckster/releases/tag/v0.8.0).

### Diagram design controls

Brands can set connector widths and patterns, drawing alignment, node sizes, subtitle and note typography, and icon borders. Slides can override placement, node dimensions and connector strokes, and use bundled or HTTPS image icons. Asynchronous calls, replies and error connectors still draw dashed. Timelines use the brand's regular width when the edge stroke is a named step. PowerPoint keeps diagram shapes editable and embeds image icons as pictures. [Design controls for diagrams](/data-and-diagrams/diagram-design/) · [PR #29](https://github.com/sandrinodm/deckster/pull/29)

### Brand imports and custom layouts

- `deckster brand add` cleans SVG artwork while staging a Git import. It warns when it removes unsupported markup and stops the install when an SVG is invalid. [SVG artwork during installation](/brands/use-a-brand/#svg-artwork-during-installation)
- The active brand's `layouts.ts` is read as static data. The build reports MDX slide content outside named slots if the brand layout lacks a body region. [Write layouts.ts](/brands/brand-layouts/#write-layoutsts) · [MDX body content](/brands/brand-layouts/#mdx-body-content)
- The agent's `new_slide` tool uses the live session's brand when it looks up a layout and scaffolds its example. [Scaffold a slide in the session brand](/ai-agents/mcp-tools/#scaffold-a-slide-in-the-session-brand)
- A PowerPoint export writes two distinct body placeholders for a brand layout mapped to two-content. [Brand layouts in PowerPoint](/brands/brand-layouts/#in-powerpoint)

[PR #31](https://github.com/sandrinodm/deckster/pull/31)

### Choosing layouts and importing templates

The presentation skill pairs each of the 63 built-in layouts with a reason to choose it. The docs show those layouts, step previews and live example decks in Fieldnote. You can compare all five brands in the [brand gallery](/examples/brands/). The brand-import skill shows how to map template placeholders to regions and choose a fallback layout. Both guides explain how to check which diagram and export features the installed CLI supports. [Choose a layout](/reference/layouts/#choose-a-layout) · [Use the skills](/ai-agents/skills/) · [PR #32](https://github.com/sandrinodm/deckster/pull/32)

## v0.7.0

The lookbook adds 24 examples for product demos, pitches, roadmaps and strategy reviews. Eleven reusable layouts, three charts and four interactive demo components have new reference entries. [Explore the examples](/examples/presentation-patterns/) · [PR #26](https://github.com/sandrinodm/deckster/pull/26)

You can now switch decks by their opening slides in the browser and desktop presenter. Brand imports validate layouts before installation and preserve existing brands if a replacement fails. [Release notes](https://github.com/sandrinodm/deckster/releases/tag/v0.7.0) · [Previous releases](/project/releases/#what-changed).

### Credential-safe brand sources

`deckster brand add` checks the source before logging it. Invalid addresses are omitted from error messages, and a failed fetch reports the Git step without copying raw Git diagnostics. Use your credential helper or SSH key to fetch a private brand. [Authentication and fetch troubleshooting](/brands/use-a-brand/#authenticate-to-a-private-repository) · [PR #20](https://github.com/sandrinodm/deckster/pull/20)

### Transaction-safe brand installs

`deckster brand add` stages a complete brand before publishing it. Installs of the same brand run one at a time. On retry after an interruption, the installer restores the previous brand if publication was incomplete. If publication finished, it keeps the new brand and cleans up the backup. If recovery is blocked, the error gives the saved copy's location. [Recover an interrupted replacement](/brands/use-a-brand/#recover-an-interrupted-replacement) · [PR #21](https://github.com/sandrinodm/deckster/pull/21)

### Brand layout validation before install

The importer checks `layouts.ts` against the layout catalog before installing or replacing a brand. Errors leave the installed brand in place, and warnings identify the file and field to fix. [Layout checks during installation](/brands/check-a-brand/#layout-checks-during-installation) · [PR #23](https://github.com/sandrinodm/deckster/pull/23)

### Browser deck chooser

Run `deckster dev` without a deck argument or `DECK` in a workspace with several decks. The command prints a chooser URL where you can pick a deck by its title, folder name or a preview of its first visible slide. This includes workspaces with a `hello` deck. [Choose a deck in your browser](/get-started/workspace-layout/#choose-a-deck-in-your-browser) · [PR #22](https://github.com/sandrinodm/deckster/pull/22)

### Desktop presentation gallery

`deckster present` opens the workspace gallery when several decks are available and neither a deck argument nor `DECK` is set. Choose a deck to start the presentation, then return to the gallery to switch talks. The display options still apply to the audience and presenter windows. [Choose a deck in the desktop gallery](/present/deck-present-and-displays/#choose-a-deck-in-the-desktop-gallery) · [PR #24](https://github.com/sandrinodm/deckster/pull/24)
