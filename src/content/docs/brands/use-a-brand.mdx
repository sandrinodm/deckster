A brand is a folder under `brands/` that sets a deck's colours, type, logo, icons and motion. This page shows you how to add one of the published brands, or a brand from any git repository, to your workspace, pick a brand for a deck, and render the same deck in another brand without editing a slide.

<BrandGrid slide="review-rounds" />

## Which brands you have

Only `default` ships with the npm CLI. It works in every workspace, even one without a `brands/` folder. The other four published brands, `nocturne`, `fieldnote`, `kinetic` and `tidewater`, are folders in the [repository's `brands/` folder](https://github.com/sandrinodm/deckster/tree/main/brands). `deck brand add` copies one into your workspace, and so it does any brand folder in a git repository you can read.

## Add a published brand

These steps add `nocturne` to a workspace called `talks`. The other three work the same way. Only the font packages differ, and `deck brand add` names them.

<Aside type="note" title="New in v0.6.0">
`deck brand add` needs `@deckster/cli` 0.6.0 or later. 0.5.0 reads `add` as a brand name and prints `No such brand in brands/add/brand.ts`; with it, copy the brand's folder from a clone of the repository into `brands/` and delete its `package.json` and `tsconfig.json`.
</Aside>

<Steps>

1. Add the brand from the repository, at the tag of the CLI you run, so the brand and the CLI match. It needs `git` on your `PATH`:

   ```console
   $ deck brand add gh:sandrinodm/deckster/brands/nocturne#v0.6.0
   Fetching gh:sandrinodm/deckster/brands/nocturne#v0.6.0 with git...
   Added brands/nocturne/ from gh:sandrinodm/deckster/brands/nocturne#v0.6.0 at 67418e3 (4 files).
   Left out: package.json (package file), tsconfig.json (package file).
   Next:
     npm install @fontsource-variable/fraunces@5.3.0 @fontsource-variable/manrope@5.3.0 @fontsource/ibm-plex-mono@5.3.0
     deck brand check nocturne
   ```

   It writes `brands/nocturne/` with `brand.ts`, the two logos and the README, and leaves out the `package.json` and `tsconfig.json` that tie the folder to the repository. Fonts are not installed: the `Next:` lines say what to run, with the versions the brand's own `package.json` pins.

2. Install the font packages in the workspace folder, the one that holds `decks/` and `brands/`. If it has no `package.json`, `npm install` creates one.

   ```console
   $ npm install @fontsource-variable/fraunces@5.3.0 @fontsource-variable/manrope@5.3.0 @fontsource/ibm-plex-mono@5.3.0

   added 3 packages in 2s

   3 packages are looking for funding
     run `npm fund` for details
   ```

3. Check the brand:

   ```console
   $ deck brand check nocturne
   brands/nocturne/brand.ts
   nocturne: is valid (0 errors, 0 warnings).
   ```

   Before the fonts are installed, the check fails with one error per package, such as `typography.families.display.source.package: @fontsource-variable/fraunces is not installed for brands/nocturne.`

</Steps>

The CLI already carries the fonts of `default` (Bricolage Grotesque, Inter and JetBrains Mono), so a brand that uses only those needs no install. [Check a brand](/brands/check-a-brand/) explains the rest of what `deck brand check` reports.

## Add a brand from another repository

`deck brand add <source>` works with any git repository your `git` can read. The source names the repository, the folder that holds `brand.ts`, and optionally a ref after `#`, a branch, a tag or a full 40-character commit. Without a ref it takes the default branch.

| Source | Example |
| --- | --- |
| `gh:<owner>/<repo>/<folder>#<ref>`, over HTTPS | `gh:acme/brand-kit/brands/acme#v2` |
| A GitHub link to the folder | `https://github.com/acme/brand-kit/tree/v2/brands/acme` |
| Any HTTPS or SSH address, with the folder after `//` | `git@github.com:acme/brand-kit.git//brands/acme#v2` |

It runs your own `git`, so your credential helper, SSH key and `url.<base>.insteadOf` rules apply, and a private repository works when `git clone` would. It fetches only that folder, at the commit the ref names, and each network step may take up to two minutes. The folder is named after the brand's `name` in `brand.ts`, not after the folder in the source.

What it copies and what it refuses:

- **Data, not code.** `brand.ts` and `layouts.ts` are read as data and never run, and a `brand.ts` that is more than one `defineBrand` call around plain values is refused. The brand is checked before anything is written, and `deck brand check`, once its fonts are installed, checks what needs them.
- **Only brand files.** `brand.ts`, `layouts.ts`, images (`svg`, `png`, `webp`, `jpg`, `jpeg`), fonts (`woff2`, `woff`, `ttf`, `otf`), documents (`md`, `txt`, `json`) and licence files. Other code, symlinks, hidden files and package files (`package.json`, lock files, `tsconfig.json` and the like) are left out, and `Left out:` lists them. At most 500 files and 50 MiB.
- **No overwrite.** When the workspace already has a brand of that name, it stops: `The workspace already has brands/nocturne/.` Pass `--force` to replace it; the output then starts with `Replaced`, and a failed copy puts the old folder back.

A source that is not a brand folder fails before anything is written:

```console
$ deck brand add gh:sandrinodm/deckster/decks/hello#v0.6.0
Fetching gh:sandrinodm/deckster/decks/hello#v0.6.0 with git...
gh:sandrinodm/deckster/decks/hello#v0.6.0 has no brand.ts, so it is not a brand folder.
Point at the folder that holds brand.ts, such as gh:owner/repo/brands/<name>.
```

`--json` prints `{ ok, brand, dir, source, commit, replaced, files, written, skipped, fonts, warnings, next }`: `skipped` has each left-out file with its reason, `fonts` each font package with its version and whether it is `installed`, and `next` the commands to run. The full help is under [`deck brand`](/reference/cli/#cli-brand).

## Which brand a deck uses

A deck names its brand in `deck.config.ts`. `deck new` writes it, `default` unless you pass `--brand`:

```console
$ deck new board-update --brand nocturne
decks/board-update/deck.config.ts
decks/board-update/slides/title.mdx
Next: run `deck dev board-update`. For editor type checking, run `deck types` once (again after upgrading @deckster/cli).
```

```ts
import { defineDeck } from '@deckster/engine/config';

export default defineDeck({
  title: 'Board update',
  brand: 'nocturne',
  slides: ['title'],
});
```

Change `brand:` to switch the deck for good. A deck config without a `brand` key uses `default`. The brand must already be in the workspace. Before you add `nocturne`, the same command fails:

```console
$ deck new board-update --brand nocturne
There is no brand "nocturne". Brands: default.
Run `deck new --help` for the usage.
```

## Render a deck in another brand

To try a brand without touching the deck, pass `--brand <name>` to `deck dev`, `present`, `shot`, `lint`, `diff` or `export`. The slides stay the same; the brand changes every colour, family, size and logo they draw.

```sh
deck dev launch-review --brand nocturne
deck lint launch-review --brand nocturne
deck shot launch-review --brand nocturne
```

Commands that write files keep each brand apart with an `@<brand>` suffix: `deck shot` writes to `.deck/shots/launch-review@nocturne/`, `deck export` to `.deck/exports/launch-review@nocturne`, and `deck diff` adds the same suffix to its folders. `deck present --built` can't be combined with `--brand`. To compare a deck across every published brand at once, see [one deck in every brand](/examples/brands/).

## Icons when you switch brands

Each brand draws its icons from one Iconify set: `default` and `tidewater` use Lucide, and `nocturne`, `fieldnote` and `kinetic` use Tabler. An icon name that exists in only one set breaks the deck in the other brand. Say a `risks` slide of `launch-review` has `<Icon name="arrow-big-down-dash" />`, a Lucide name. `deck lint launch-review` passes, but in `nocturne` lint reports the icon, and `deck dev` shows the same error:

```console
$ deck lint launch-review --brand nocturne
decks/launch-review/slides/risks.mdx
  error   schema (risks): Line 21, column 3: <Icon name="arrow-big-down-dash"> is not an icon of the tabler set.
          Fix: Closest names in the tabler set: arrow-big-down-line, arrow-big-down, arrow-big-down-lines, arrow-big-down-filled, arrow-down-dashed, arrow-bar-down. Browse the set at https://icon-sets.iconify.design/tabler/. A deck that renders in several brands needs a name that every brand's set has.

launch-review: 1 error, 0 warnings.
```

For a deck that renders in several brands, pick names from `deck icons`, which lists only the names every brand you name has:

```console
$ deck icons --brand default,nocturne --search arrow-big
4 icon names matching "arrow-big" in every one of: default (lucide), nocturne (tabler)
Sets: lucide, tabler

arrow-big-down, arrow-big-left, arrow-big-right, arrow-big-up
```

Without `--brand` it uses every brand in the workspace, `default` included. The [icons reference](/reference/icons/) lists the names all five published brands share.

To make a look of your own, [create a brand](/brands/create-a-brand/), or have an agent [import one](/brands/import-a-brand/) from a template, PDF or website.
