Write a slide as an MDX file: a frontmatter block that picks the layout and sets its fields, a body in Markdown with components, and the speaker's notes. This is how most slides are written, by hand or by an agent, and what you read when you review one.

## What an MDX slide looks like

```mdx
---
layout: cards
title: Three rules decide where a tree goes
eyebrow: Planting principles
cards:
  - icon: thermometer
    title: Hottest blocks first
    text: Rank blocks by July surface heat; plant from the top.
  - icon: trees
    title: Large species only
    text: "Plane, oak and lime: crowns that shade the road."
  - icon: droplets
    title: Three summers of care
    text: Water, mulch and check every tree for three years.
budget: 40s
---

Every block in the ten-year plan passes all three.

<Notes>
Say the three rules, then say they come from the pilot: we broke each one once, and each time the trees died.
</Notes>
```

The file is `slides/<id>.mdx` in the deck folder, and the slide shows only once `deck.config.ts` lists its id. `deckster new slide <deck> <id> --layout <name>` writes the file from the layout's example and adds it to the list. The same slide rendered:

## Frontmatter

Every slide takes seven keys, whatever its layout:

| Key | What it sets |
| --- | --- |
| `layout` | The layout, by name. Default: `default`. `deckster layouts` lists them. |
| `title` | The slide's title. |
| `surface` | The brand surface: `default`, `inverse`, `accent`, `gradient` or one the brand adds. |
| `background` | A picture behind the whole slide. See [media](/write-slides/media/). |
| `budget` | How long you plan to speak, such as `40s` or `1m30s`. See [speaker notes](/write-slides/speaker-notes/). |
| `transition` | How the slide comes in. See [transitions and morphs](/write-slides/transitions-and-morphs/). |
| `hidden` | `true` keeps the slide in the deck and skips it in a talk. New in 0.5.0. See [hidden slides](/write-slides/hidden-slides/). |

Every other key belongs to the layout, such as `eyebrow`, `cards` or `ratio`. Find a layout for your slide in [Choose a layout](/reference/layouts/#choose-a-layout), then open its page for fields, slots and limits. See the common keys in [slide frontmatter](/reference/slide-frontmatter/).

Whether `title:` appears on the slide depends on the layout. Content layouts such as `cards`, `content` and `split` set it as the slide's heading. The `statement` layout shows only the statement: its `title:` names the slide in the outline. The `default` layout takes its heading from the body (`#` or `##`).

## Markdown in the body

The body is GitHub-flavoured Markdown: headings, `*emphasis*` and `**strong**`, lists, links, tables and inline code. Straight quotes become typographic ones, outside code. An image alone in its paragraph becomes an `<Image>`:

```mdx
![A residential street under a full summer canopy](../assets/street.jpg)
```

The layout's budget says how much content the body can hold. Brand layouts only accept body content if they have a region bound to `body`. [Text and fitting](/write-slides/text-and-fitting/) · [Layouts and slots](/concepts/layouts-and-slots/) · [MDX body content in brand layouts](/brands/brand-layouts/#mdx-body-content)

## Components and data

Kit components (`<Step>`, `<Notes>`, `<Image>`, `<BarChart>`, `<Flow>`, `<Code>` and the rest) need no import. Data files and your own components are imported with a path relative to the slide:

```mdx
import teams from '../data/teams.csv';

<Slope
  data={teams}
  x="team"
  from="2025"
  to="2026"
  better="down"
  highlight={['Billing', 'Payroll']}
  unit="h"
  caption="Median hours to resolve a ticket, 2025 and 2026"
/>
```

Keep Markdown inside a component separated from the tags by blank lines, and write a literal `{` or `<` in text as `\{` or `&lt;`.

To look up a component's props from the terminal, run `deckster components` (code, media, link and demo components; `--json` for agents), `deckster charts` or `deckster diagrams`. The same catalogs are on [components](/reference/components/).

In one sentence each: `<Step at={n}>` reveals content on a later press ([builds](/write-slides/builds/)); a fence is a code block ([code](/write-slides/code/)); `<Notes>` holds what the speaker says ([speaker notes](/write-slides/speaker-notes/)); images and video are on [media](/write-slides/media/).

## Fill a layout's named slots

The body fills the layout's main slot. Other slots have a tag: wrap their content in it at the top level of the slide. Which tags a layout takes is on its page under [layouts](/reference/layouts/); common ones are `<Aside>` (a column beside the body), `<Footnote>` (a source on the bottom line), `<Media>` (the picture of `split`, `image`, `title` and `section`), `<Caption>` and `<Attribution>`.

A layout that requires a slot fails the build without it:

```console
$ deckster lint launch-review
decks/launch-review/slides/harbour.mdx
  error   schema (harbour): The split layout needs its media slot.
          Fix: Add <Media>…</Media> at the top level of the slide: What the text points at: one <img> with alt text (imported from the deck's assets/ or served from its public/ folder), a chart, diagram, table or component. Photos fill the frame and are cropped to it; anything else is centred and may fill it with `height: 100%` (the frame is a size container, so `100cqh` works too).

launch-review: 1 error, 0 warnings.
```

Content of a kind the slot does not take, such as a list where it takes no bullets, is a `slot-content` error in `deckster lint`.

## Build errors and their fixes

The build checks every slide against its layout before it renders. `deckster lint` runs the same checks as `deckster build` and reports each problem with the file, the line and a fix. A key that is close to a known one names it:

```console
$ deckster lint launch-review
decks/launch-review/slides/title.mdx
  error   schema (title): "eyebrw" is not a frontmatter field.
          Fix: Rename it to "eyebrow".

launch-review: 1 error, 0 warnings.
```

A key that is close to none lists the fields the layout takes:

```console
$ deckster lint launch-review
decks/launch-review/slides/title.mdx
  error   schema (title): "subtitel" is not a frontmatter field.
          Fix: Remove it. Known fields: layout, title, surface, background, budget, transition, hidden, eyebrow, byline, date, treatment, picture, align, chrome.

launch-review: 1 error, 0 warnings.
```

Fix what the message says and save; `deckster dev` reloads the slide. The checks as a whole are on [lint](/review/lint/).
