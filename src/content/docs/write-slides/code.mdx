Put code on a slide as a fenced block, step the focus through it line by line, animate it from one version to the next with `<CodeMove>`, or type a shell session one command per press with `<Terminal>`. Each of these is a deck step, so the speaker controls the pace.

Code goes on the [`code` layout](/reference/layouts/code/): a title that says what the code shows, one block of code, and up to three short notes in `<Aside>`.

## Write a code block

A fence with a language is a code block. The words after the language set its options:

<StepStrip deck="components" slide="middleware-order" />

````mdx
```ts title="server.ts" {3-5|4|7} lineNumbers /authenticate/
const app = createApp();

app.use(cors());
app.use(authenticate());
app.use(rateLimit({ perMinute: 60 }));

app.get('/orders', listOrders);
app.listen(3000);
```
````

Step 0 shows the whole block. Each part of `{3-5|4|7}` is one press: the named lines stay at full strength and the rest fade back. The strip above shows the four steps.

| Option | What it does |
| --- | --- |
| `title="server.ts"` or `file="server.ts"` | The file name in the title bar. A bare quoted string (`"server.ts"`) does the same. |
| `{2-4\|7}` | Highlight steps, separated by `\|`. A step names lines and ranges, comma-separated (`2-4,7`). `*`, `-` or `none` clears the focus for that step. |
| `at=2` | The step of the first highlight. Default 1. |
| `lineNumbers` | Show line numbers. `showLineNumbers` and `numbers` work too. |
| `start=10` | The number of the first line. |
| `diff` | A leading `+` or `-` marks an added or removed line, tinted in the surface's diff colours. |
| `/word/` | Mark a word wherever it occurs as a whole word. Repeat for more words. |
| `noDim` | Keep lines outside the highlight at full strength. |
| `label="TS"`, `noLabel` | Change or hide the language label in the title bar. |

Anything else stops the build. In `deckster lint`:

```console
$ deckster lint launch-review
decks/launch-review/slides/query.mdx
  error   schema (query): Line 6, column 1: "lines" is not a code block option. Use title="file.ts", {2-4|7}, /word/, lineNumbers, diff, noDim, noLabel, label="TS", start=10 or at=2.
          Fix: Close every JSX tag, keep markdown inside a component separated by blank lines, and escape a literal { or < in text as \{ or &lt;.

launch-review: 1 error, 0 warnings.
```

A `diff` fence shows a change in one block:

<SlideExample deck="components" slide="user-or-401" />

Highlighting runs when the deck is built, and the colours are the brand's code colours for the slide's surface, so the same block reads on every surface and in every brand. Lines that start with `+` or `-` without `diff` stay as written; a trailing `// [!code ++]` or `// [!code --]` comment marks a single line instead.

## Use `<Code>` instead of a fence

A fence covers almost every case. Write `<Code>` when the code comes from a variable, most often in a [TSX slide](/write-slides/tsx-slides/): it takes the same options as props (`code`, `lang`, `file`, `lineNumbers`, `start`, `highlight`, `at`, `dim`, `diff`, `words`), and `highlight` also takes a list or an object keyed by step, such as `{ 1: '3-5' }`. A `<Code>` in a TSX slide is highlighted in the browser, and the slide waits for it before it counts as ready. Every prop is on [components](/reference/components/#props-Code).

## Animate code as it changes

`<CodeMove>` holds one fence per version. The first shows on arrival, and each press moves to the next: tokens that stay glide to their new place, so the room can follow which line became which.

<StepStrip deck="components" slide="handler-evolves" />

````mdx
<CodeMove file="orders.ts">

```ts
export function listOrders(req, res) {
  db.orders.where({ userId: req.user.id }, (err, rows) => {
    res.json(rows);
  });
}
```

```ts
export async function listOrders(req, res) {
  const rows = await db.orders.where({ userId: req.user.id });
  res.json(rows);
}
```

</CodeMove>
````

Keep blank lines around each fence inside the tag. `at` sets the step of the second version (default 1). For a version a fence cannot express, such as a different language, write a `<CodeStep lang="js">` in its place. Four versions is the most a room follows.

## Show a shell session

`<Terminal>` types its commands one press at a time. Each `<Cmd>` adds one step, and the `<Out>` lines after it appear once the command is typed:

<SlideExample deck="components" slide="deploy" />

- With the default `at={1}`, the terminal arrives with only the prompt and a cursor; `at={0}` types the first command on arrival. A `<Cmd>` has no `at` of its own.
- `<Out>` written before the first `<Cmd>` shows from step 0.
- `<Out tone>` colours a line: `plain` (default), `muted`, `success`, `warning` or `error`.
- `title` sets the window bar (default `Terminal`) and `prompt` the prompt (default `$`).

A command is kept exactly as written, so URLs and `*` stay text. Show the two lines of output that matter, not the log.

## How much code fits

At most 11 lines, and lines of at most 60 columns beside an `<Aside>` or 90 without one. The `code` layout's budget is 11 lines: more is a `content-budget` error. Long lines step the font down to the brand's minimum and then overflow, which `deckster lint` reports as well. Cut the code to the lines you talk about, or split the slide.

## What lint warns about

Three problems in code reach `deckster lint` from the build as warnings:

```console
$ deckster lint launch-review
decks/launch-review/slides/query.mdx
  warning code-unknown-language (query): Line 6: Unknown code language "sqll"; the block is shown as plain text.
          Fix: Use a Shiki language id such as ts, tsx, bash or json.

decks/launch-review/slides/middleware.mdx
  warning code-step-range (middleware): Line 7: The highlight step at 2 names line 9, but the block has 2 lines.
          Fix: Number the lines from 1 to 2 in `{...}`, or remove the step; a step that names no line of the block is a press that changes nothing.

decks/launch-review/slides/deploy.mdx
  warning terminal-tone (deploy): Line 9: <Out tone="green"> is not a terminal tone, so the line draws plain.
          Fix: Use one of "plain", "muted", "success", "warning", "error".

launch-review: 0 errors, 3 warnings in 3 slides (6 steps checked).
```

## In static mode and exports

Static mode, `deckster shot` and exports draw the step they render: that step's highlight and `<CodeMove>` version, and the terminal session typed up to it, as in the strips above. An export of the whole slide shows its last step. How code becomes PowerPoint is on [PowerPoint](/export-and-publish/powerpoint/). For more on steps, see [builds](/write-slides/builds/) and [steps](/concepts/steps/).
