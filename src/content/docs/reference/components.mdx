## How props are checked

Each component takes only the props its table lists. Any other name is refused with the closest prop, when one is close, and the list of props the component takes ("`href` is not a prop of `<Download>`. Did you mean `file`? Its props are: file, variant, children."), and so is a missing required prop: at build time in an MDX slide, and when the slide renders in a TSX slide. None of these components shares props with another, so no row is marked "shared".

The catalog states a few rules that hold for all of them:

- **Files.** Paths to images, video, posters and Lottie files are relative to the slide file and become imports. A missing file is reported by `deck lint` as `media-missing`. A Markdown image alone in its paragraph becomes an `<Image>`.
- **Static mode.** Static mode, `deck shot` and the exports never play video or load frames: they show posters, the last state of a `<CodeMove>`, and the whole terminal session up to the step.
- **Steps.** Code highlights, `<CodeMove>` states, `<Terminal>` commands, `<Video>` cues and `<AppFrame>` steps are deck steps: each press moves one.
- **Build warnings.** What the build warns about reaches `deck lint` with a rule id: `media-missing`, `media-gif`, `code-unknown-language`, `code-step-range` and `terminal-tone`.

`deck components --json` prints the same catalog. The `<LinkCard>` and `<Step>` below are the deck components, not the ones this site uses.
