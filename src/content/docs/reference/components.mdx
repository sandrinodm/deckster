## How props are checked

Each component takes only the props its table lists. Any other name is refused with the closest prop, when one is close, and the list of props the component takes ("`href` is not a prop of `<Download>`. Did you mean `file`? Its props are: file, variant, children."), and so is a missing required prop: at build time in an MDX slide, and when the slide renders in a TSX slide. No row is marked "shared": `<Place>`, `<Shape>` and `<Text>` take the same placement props, and each of their tables lists them.

The catalog states a few rules that hold for all of them:

- **Files.** A path to an image, video, poster or Lottie file starts at the slide file when it begins with `./` or `../`, at the deck folder when it is bare (`assets/x.png`), and at the deck's `public/` folder when it begins with `/`. Files in the deck folder become imports; `public/` files are served as they are. A missing file is reported by `deckster lint` as `media-missing`. A Markdown image alone in its paragraph becomes an `<Image>`. See [where a path points](/write-slides/media/#where-a-path-points).
- **Static mode.** Static mode, `deckster shot` and the exports never play video or load frames: they show posters, the `<CodeMove>` version of the current step without animation, and the whole terminal session up to the step.
- **Steps.** Code highlights, `<CodeMove>` states, `<Terminal>` commands, `<Video>` cues and `<AppFrame>` steps are deck steps: each press moves one.
- **Build warnings.** What the build warns about reaches `deckster lint` with a rule id: `media-missing`, `media-gif`, `code-unknown-language`, `code-step-range` and `terminal-tone`.

`deckster components --json` prints the same catalog. The `<LinkCard>` and `<Step>` below are the deckster components, not the ones this site uses.

## Product and AI demonstrations

These v0.7.0 components use data you write in the slide. Put one in the body of a `demo` slide. Each includes a default sequence of deck steps and renders its own still for export. [Demo layout](/reference/layouts/demo/) · [Presentation patterns](/examples/presentation-patterns/)

### CommandDemo

Put the command you want to run with the deck’s advance key first in `commands`. In the open palette you can also select another command and read its authored result. [Command palette example](/decks/lookbook/#/command-palette)

<PropsTable of="CommandDemo" />

### GroundedAnswer

Use `context` for the surrounding text and `evidence` for the exact supporting words. Activating the citation moves keyboard focus to that passage. [Grounded answer example](/decks/lookbook/#/ai-grounded-answer)

<PropsTable of="GroundedAnswer" />

### ReviewDiff

Supply the original words and the replacement with their surrounding text. Choose **Accept edit** or **Keep original** in the live slide to read the whole draft with that choice applied. [Review example](/decks/lookbook/#/ai-review-diff)

<PropsTable of="ReviewDiff" />

### RunTrace

Give each call the input the audience should see and the observation it returns. Use `checkpoint` to say what a person must decide and `outcome` to show what is ready for review. [Run trace example](/decks/lookbook/#/agent-run-trace)
