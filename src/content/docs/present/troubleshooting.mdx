Each section below is a symptom or the exact message `deckster` prints, what causes it and the fix, for problems just before or during a talk. Build and lint errors are on their own pages.

## "Electron ... is not downloaded"

```text
Electron 45.4.1 is not downloaded, so `deckster present` cannot open a window.
Run `deckster electron install` once (about 120 MB), or pass --browser to present in Chrome.
```

npm installs Electron's package but often not its binary. Run `deckster electron install` once. If it was downloaded for an older CLI, `deckster electron status` says so and `deckster electron update` replaces it. When the download fails, the command says why (no write permission, network or proxy, checksum) and how to fix it. With no time for a 120 MB download, present with `deckster present <deck> --browser`, or `deckster dev <deck>` in any browser. See [deckster present and displays](/present/deck-present-and-displays/).

## "The electron package is not installed"

```text
The electron package is not installed, so `deckster present` cannot open a window.
Electron is an optional dependency that the install skipped or could not fetch: reinstall @deckster/cli, or pass --browser to present in Chrome.
```

`electron` is an optional dependency of `@deckster/cli`, and this install left it out. Reinstall `@deckster/cli` with its optional dependencies, or use `--browser`.

## "The Electron shell did not report ... within the start-up timeout"

```text
The Electron shell did not report its displays within the start-up timeout. Run the command again; if it keeps failing, check that the deck URL loads in a browser.
```

The window process gets 45 seconds to report the displays after it starts, and again to load the page once the deck is served; the second wait names "the window loaded" instead of "its displays". Loading and building the deck do not count against it. Run the command again. If it fails again, open the URL from the `Presenting ... at` line in a browser: a build error shows there.

A related line, `Warning: the window loaded the page, but no deck is running in it. Open the URL in a browser to see its errors.`, means the page loaded but the deck failed to start; the browser shows why.

## A deck fails to open from the gallery

Read the message in the chooser. To diagnose a deck that fails to load, open it by folder name with `deckster present <deck> --browser`. If the failure occurred with `--built`, run `deckster build <deck>` to see the build errors. Fix the error, then select the deck again. See [Choose a deck in the desktop gallery](/present/deck-present-and-displays/#choose-a-deck-in-the-desktop-gallery).

## "Could not prepare Deckster.app (...); the window will show as "Electron""

On macOS, `deckster present` builds a copy of Electron's app named Deckster in `.deck/shell/app/`. When that fails (the reason is in the brackets), it runs Electron's own app instead: the deck works, but the Dock and the menu bar say Electron. Since v0.6.1 the CLI retries with a recursive copy that preserves framework links if the copy tool rejects the macOS clone option. If you saw that warning on an earlier version, upgrade the CLI and run `deckster present` again. For other failures, fix the reported cause, or delete `.deck/shell/app` so the next `deckster present` builds it again.

## The window stays blank

Open View > Toggle Developer Tools (Alt+Cmd+I on macOS, Alt+Ctrl+I elsewhere) and read the console. View > Reload (Cmd/Ctrl+R) loads the page again.

## Keys do nothing

- **A text field has focus.** Keys typed into a text field are ignored by the deck. The agent panel's input keeps every key while it has focus; press Escape to give the keys back to the deck.
- **A panel is open.** Help, the overview and go-to take the keys while they are open; Escape closes them.
- **The screen is blacked out.** The first navigation key brings the slide back; the next one moves.
- **You clicked an element.** Clicks on buttons and links in a slide go to that element, not to the deck, and so does Space pressed on one.

The keys themselves are in [Keyboard shortcuts](/reference/keyboard-shortcuts/).

## The presenter window does not open in a browser

`p` opens the presenter window as a pop-up, which a browser's pop-up blocker can stop. Allow pop-ups for the deck's address, or open it yourself with `?presenter` before the hash, for example `http://127.0.0.1:5173/?presenter`. Use the same browser as the audience window: the two windows only stay in step within one browser. See [Presenter tools and shortcuts](/present/presenter-tools-and-shortcuts/).

## "Port 5173 is already in use"

```console
$ deckster present launch-review --port 5173
Error: Port 5173 is already in use
...
```

`--port <n>` takes that port or fails; the rest of the output is a stack trace. Stop the other server, or leave `--port` out: without it, `deckster dev` takes the first free port from 5173 and `deckster present` a free port the operating system picks.

## The window shows an older version of the deck

Before 0.10.0, `deckster present` could share a port with a `deckster dev` server that was still running: one listened on `127.0.0.1` and the other on `localhost`, which macOS resolves to the IPv6 address `::1`, so neither saw the port as taken and the window could load the dev server's deck. Upgrade to 0.10.0: both servers listen on `127.0.0.1`, `deckster present` picks a free port of its own, and it warns about a dev server that is still running:

```console
Warning: a dev server for "launch-review" is still running at http://127.0.0.1:5173/ (process 12345). This presentation uses its own server; stop the dev server if you no longer need it.
```

Stop that server with Ctrl+C in its terminal if you no longer need it.

## A link opens in my browser, not in the window

By design. The `deckster present` window shows only the deck's own pages. A link to another site opens in your default browser (web and `mailto:` links, at most 3 in 10 seconds across all its windows), and downloads are refused. For a deck that offers a file to download, present with `--browser`.
